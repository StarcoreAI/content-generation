## 1. 背景诊断：为什么重构

现有链路的四个病根，都指向同一个结构问题——**散文进、散文出，中间没有结构化层**：

1. **客户资料直塞**：旧 `services/materials.py` 曾用行业写死规则抽取资料，换行业就失效；资料整包直接拼接进写作提示词，模型容易整段照搬。固定 12000 字截断已删除，但这不替代后续按任务整理资料的工作。短期先删除旧行业规则，不在这里建设逐条资料库。
2. **引用情报合并压颗粒度**：三阶段流水线（stage1 逐篇抽结构 → stage2 聚类合并 → stage3 改写成 prompt_text + few_shot 插件）在 stage2 把 N 篇文章压成一条"开头以政策收紧为背景"式的指令，每篇生成文章都执行同一条，开头结尾雷同的根源在此。插件按批次绑定、用完即弃，没有积累。
3. **竞品资料无结构**：竞品资料输出为合并 Markdown，写作时整包注入，导致张冠李戴（把 A 竞品的事实安到 B 头上）、复读竞品自我宣传。
4. **联网扩展带枷锁且输出散文**：`services/material_web_expansion.py` 的提示词明确禁止检索优势类信息，且要求输出长篇散文——这是"运营反馈资料里看不出品牌优势"的直接原因。

加上两个功能缺口：没有批量生成（运营一篇篇点）；历史记录是线性的按天按类型列表，没有"在已有文章上 AI 修改"的版本链。

## 2. 关键证据：五篇高频引用文章的分析结论

2026-07 人工分析了豆包/DeepSeek/元宝的五篇高频引用文章（教培行业，河北成人学历提升），结论作为本次设计的事实依据：

1. **高频引用文章池 = 双方投放战场**。五篇中四篇可确认为我方客户（翼升学）或其竞品（翼程教育）的付费投放软文，发布在地方新闻站（邢台网、黄冈新闻网）或品牌官网知识页。存在专为 AI 爬虫设计的痕迹：隐藏的 DeepSeek/豆包友链、对本地 IP 的 cloaking、FAQ 问题直接用"请帮我推荐"这种对 AI 说话的句式。
2. **playbook 已收敛**：政策背景开头 → 评测维度（常带权重百分比）→ 梯队/排名 → 首推详述 → 其他简评 → 对比表 → 分人群建议 → FAQ → 结语。相似不是巧合，是同一套模板。
3. **引用友好信号**：标题带年份+地域+决策词、有官方时间/数字锚点、有对比表、有 FAQ（问题为用户原话句式）、有数据来源声明、有分人群建议。
4. **竞品放大器风险**：竞品联网资料本质是竞品的自我宣传（翼程的"95% 通过率、21 省直营"），我方文章客观转述等于免费帮竞品做 GEO。竞品自述必须标记来源类型，强主张禁止复读。
5. **低质文章也会被高频引用**：存在标题写"多机构对比"正文只吹一家的文章进入高频引用池。"被引用"不等于"值得学习"，引用情报必须先过滤。
6. **合规路线可行**：最中性的观察体文章（明确标注"本内容为广告"、不拉踩、不排名）同样被 DeepSeek 引用。系统坚持不拉踩、不点名贬损。

## 3. 目标架构总览

```text
引用情报分析 ──产出──> 写法库（骨架模板 + 段落模式 + 引用友好度清单）
客户资料解析 ─┐
客户联网扩展 ─┴─产出──> 客户资料包（资料摘要 + 定位素材 + 人群痛点 + FAQ 素材 + 缺口报告）
竞品资料扩展 ──产出──> 竞品实体库（结构化条目 + 来源类型 + 强主张清单 + 置顶/拉黑）
问题组（已有）──────> FAQ 问题来源

                 ┌── 抽样器（代码）：骨架 × 开头 × 结尾 × 竞品子集 × 人群角度 × FAQ 子集
内容生产 = 批量任务┤
                 ├── 策划简报 LLM：组合 + 库条目 -> 结构化简报（入库，溯源）
                 ├── 写作 LLM：简报 + 客户资料摘要 -> 文章
                 └── 质量门禁：代码层 + LLM 层 -> 检查报告（入库）

版本修改链：文章带 parent_id / root_id，AI 修改只取本链上下文
```

核心原则：

- **每个模块只产出结构化、可审核、带来源的中间件，不产出可照搬的成品散文。**
- **所有分析产物往持久库增量入库、比对去重，不搞每轮重新合成。**
- **多样性靠机械组合抽样，不靠嘱咐 LLM"写得多样"。**
- **运营审核点前移到审资料（资料包、竞品库），而不是审 3000 字成文。**

## 4. 数据模型

所有库条目带三个通用字段（短期就建，长期进化机制才用得上但字段现在就要有）：

- `scope`：`global` / `industry:<行业名>` / `client:<cid>`（作用域，读取时按 客户 ∪ 行业 ∪ 全局 合并）
- `status`：`candidate`（候选）/ `active`（生效）/ `retired`（停用）。抽样器只从 `active` 抽。
- `valid_until`：可空。有时效的条目（政策事实等）过期后自动降级为仅历史参考，并进缺口报告。

### 4.1 写法库 `data/pattern_library/<scope>.json`

三类条目：

**骨架模板（skeleton）**：`skeleton_id`、名称、来源文章（URL+日期+引用平台）、适配子类型、基调、章节序列（每节功能一句话）、识别特征、风险提示、证据计数 `evidence_count`。

**段落模式（module）**：`module_id`、类型（开头/结尾/FAQ段/对比表/其他）、名称、套路描述（必须是"换品牌换事实还能照做"的形状，不是内容）、例文片段（真实引用文章节选，仅作示范）、适配骨架、证据计数。

**引用友好度清单（citability checklist）**：可检查特征列表，供门禁提示层和简报 LLM 使用。

### 4.2 客户资料包 `data/material_packages/<cid>/`

短期不新建逐条客户知识库。客户资料先沿用现有产物：

- `latest_injection.md`：客户上传资料经过筛选、去重、压缩后的主资料包。
- `latest_web_supplement.md`：联网补充材料，只作为资料补充，不直接当成客户承诺。
- 内容生产页允许运营显式选择是否使用上述两个资料包；内容生产独立上传资料继续保留，并可逐份启用/停用。
- 后续内容生产的一阶段信息整理 LLM，按具体文章任务从上述资料中整理“本次必须覆盖的信息、可展开角度、缺口提示”和禁用项。
- 明显矛盾、夸大、无来源的判断放到质量门禁阶段处理。

当前阶段只要求资料包干净、行业无关、可被生成 prompt 稳定读取。

`latest_injection.md` 当前按八个方向组织：品牌基础、产品与服务、核心优势、目标人群与需求痛点、价格与费用表达、信任凭证、合规风险表述、行业公共背景。资料没有的不编造，登记到“缺口与检索提示”；人群痛点可推断但必须标“推断，待确认”；价格只保留原文；绝对化、承诺类、无法证实数字集中列为“限制使用”。

`latest_web_supplement.md` 当前按三类 GEO 素材组织：品牌公开信息与优势表达角度、人群痛点与决策语境、行业公共背景锚点。它只扩素材，不做事实核验、不做冲突仲裁、不替客户“洗白”强主张。

### 4.3 竞品实体库 `data/competitor_library/<cid>.json`

每个竞品实体一条：名称（真实名，禁占位名）、结构化字段（定位/业务/规模/资质/价格，每字段带来源类型：竞品自述/第三方/投放软文）、**强主张清单（禁止放大）**、**安全描述**（中性一句话+适合人群，供"其他机构简评"段落使用）、冲突标记（同一字段多来源矛盾时）、运营控制位（置顶/拉黑）。

### 4.4 内容生成记录（SQLite，扩展现有 `ContentGenerationStore`）

文章表新增列：`parent_id`、`root_id`（版本链）、`batch_id`、`brief_json`（简报原文）、`provenance_json`（用了哪个骨架/模块/资料要点/竞品/FAQ 问题）、`gate_report_json`（门禁报告）、`modify_instruction`（本次 AI 修改的运营指令原文——长期经验库的原料，现在白捡）。

新增批次表：`batch_id`、客户、创建时间、组合配置 JSON、总数/完成数/拦截数/失败数、状态。

## 5. 各流水线设计

### 5.1 引用情报：四步替代三阶段

**第 0 步 过滤与定性**（代码+LLM）：

1. 一稿多发归并（shingle 相似度），归并后记录铺站数量；
2. 低质过滤，硬标准：标题-正文一致性（标题含"对比/测评/TOP/哪家好"→ 正文实质覆盖 ≥3 家机构，代码先做机构名实体计数预检，LLM 复核）、结构完整性（能切出章节）、信息密度（有可核验锚点）、正文抓取完好；
3. 定性标记：谁的投放（我方/竞品/第三方）、风险手段（点名贬损、cloaking 等，标记"手段禁用"但结构仍可学习）；
4. 处理结果三档：**可学习**（进第 1 步）/ **仅计数**（低质但被引用，留情报不入库）/ **剔除**。

**第 1 步 逐篇抽取**：每篇一次 LLM，产出"文章解剖卡"：骨架 + 段落模式候选 + 引用友好特征 + 风险标记。限额：每篇最多 1 个骨架 + 3 个段落模式候选。提示词要求只抽"可复用的套路"，不抽内容特异性。

**第 2 步 入库比对**：新抽取物与库（含候选区）比对——库小（几十条），把现有条目名称+摘要给 LLM 判断"同一套路还是新套路"。同一 → 证据计数 +1，可补更好例文；新 → 建候选条目（`status=candidate`，计数 1）。

**晋升/降级规则**：候选在**来源独立**的文章中出现 ≥2 次（一稿多发算一次）或运营手动批准 → `active`；长期计数不涨的候选季度归档；`active` 条目可被运营停用。

**取消 stage3**：不再改写成 prompt_text + few_shot 插件。库条目直接作为简报 LLM 的输入。旧 `services/reference_stage3.py` 和插件写入逻辑已删除；历史插件读取兼容层等内容生产切换后再清理。

**当前状态**：上述 stage0、stage1、stage2 与审批页已完成、通过真实批次验证，并已接管引用情报 job。下一步是内容生产只消费运营转正的 `active` 条目；完成生成实测后，再清理历史插件读取兼容层。

### 5.2 客户资料解析：已落地的轻量资料包

现有机械抽取 / Filter / Reducer / Output pipeline 保留，继续负责清洗、去重、压缩资料，输出 `latest_injection.md`。输出 prompt 已按八个方向组织客户资料，不再维护旧行业规则或旧垂直行业样例。

本阶段不新增逐条资料库、不做运营逐条审核界面。哪些内容必须写、哪些角度适合展开，放到内容生产一阶段的信息整理 LLM 中按任务生成；明显矛盾、夸大、无依据的内容，放到质量门禁里核查。

### 5.3 客户联网扩展：已落地的三类 GEO 素材包

1. **素材目标**：检索词生成面向三类 GEO 素材，而不是只补证据：品牌优势表达素材、人群痛点与决策语境、行业公共背景锚点。
2. **品牌优势表达素材**：围绕客户品牌自身公开信息、服务特色、模式介绍、品牌公开露出，把资料包里"仅为客户自述"的优势方向搜出更多可写角度；注意是找"怎么写"的素材，不是找证明。
3. **人群痛点与决策语境**：围绕行业通用用户顾虑、避坑话题、选择标准讨论生成词，例如"学历提升机构怎么选""XX 服务常见坑"；突出优势时用行业通用短板和用户顾虑作对照，不生成任何带竞品名的检索词。
4. **行业公共背景锚点**：保留政策时间、报名规则、官方数据类检索，必须尽量带年份和省份限定，优先官方来源。
5. **禁搜边界**：不给"限制使用"表述找证据，例如"翼升学 98% 录取率"；不生成竞品名相关词，竞品归竞品模块。
6. **结果整理**：按三类输出资料要点。优势素材写成"用户顾虑/行业现象 + 客户对应能力的表达角度"；检索结果里出现竞品名的，只取中性行业信息，涉及褒贬一律不采。
7. **轻量来源标注**：每条素材标来源 URL 和来源性质（官方/媒体/UGC/疑似投放）。不做核验、不做冲突仲裁、不做洗白审查；数字类内容来源不明也可收，但标注来源性质，是否使用交给写作规则和质量门禁。
8. **当前实现**：一轮 6 个检索词，每个词最多保留 2 条来源，总体最多 12 条；如后续质量反馈显示某方向明显不足，再考虑追加第二轮，不作为当前阻塞项。

### 5.4 竞品资料扩展：prompt 已收紧，实体库仍待做

现有上传解析和联网搜索入口保留，当前仍输出 `latest_upload_competitors.md` 和 `latest_web_competitors.md`。prompt 已要求按真实竞品名称分组、保守整理、来源带 URL 和来源性质、宣传性数字/绝对化主张集中列为“禁止在我方内容中复述”，疑似投放来源不采信为事实。

后续 Phase 1b 再把 Markdown 结果升级成竞品实体库条目（4.3 结构），并补置顶/拉黑/冲突标记界面。

### 5.5 内容生产：抽样器 + 两级 LLM

**抽样器（纯代码）**：输入运营选择（子类型、竞品置顶/拉黑、可选的人群角度），从写法库 `active` 条目抽骨架和模块、从竞品库抽子集（3-5 家，尊重置顶/拉黑）、从问题组抽 FAQ 问题子集、从客户资料包定资料侧重。模块按概率带入（FAQ 段约 80%、对比表约 60%），避免"每篇全家桶"。保留 10-15% 概率抽中"无模式自拟"槽位（探索项）。附带近期指纹（近 7 天已用组合）供简报 LLM 避让。

**策划简报 LLM**：输入抽样结果 + 相关库条目全文，自动把客户资料包里的“合规风险表述 / 限制使用”内容和竞品强主张清单带入 bans，输出结构化简报：标题候选、切入角度声明、逐节要点（每节功能/要点/引用的资料要点 id/字数预算）、禁用项（竞品强主张、限制使用的资料要点、禁用词、模板句）、去重提示。简报入库。

**写作 LLM**：输入简报 + 所引资料要点原文，执行成文。写作提示词大幅瘦身：结构决策已在简报完成，只保留语言风格、合规红线、事实忠实三类规则。`docs/content-plan.md` 第 2、3 节的写作规则继续有效，作为写作 LLM 的规则来源。

### 5.6 版本修改链

- 每篇文章带 `parent_id`（直接父版本）/ `root_id`（链头）。首次生成 parent 为空。
- 已生成文章上加"AI 修改"按钮：运营输入修改指令 → 上下文只取**本链**（root 到当前的各版本 + 各次修改指令），不混入同日其他文章 → 生成新版本挂到链上。
- 修改指令原文存 `modify_instruction` 列。
- 历史记录 UI 从"按天平铺"改为"按链分组，链内按版本排列"，支持版本对比查看。

### 5.7 一键批量生成

- 运营配置：子类型多选 × 每子类型份数（或总份数）、竞品置顶/拉黑、可选人群角度多选。提交后创建批次。
- 执行：后台线程队列逐篇执行（沿用现有后台任务/进度模式，单 worker 约束下禁止并发多篇同时调 LLM，逐篇串行或小并发按现有 LLM 调用约定）。每篇独立走 抽样 → 简报 → 写作 → 门禁，独立入库（带 `batch_id` 和溯源）。
- **批内约束**：同批内（骨架+开头模块）组合不重复；竞品子集轮换；FAQ 问题子集至多部分重叠；成文后与批内已完成文章做 shingle 相似度检查，超阈值自动重抽样重生成一次（只重试一次，仍超则标记"高相似"交运营处理）。
- 页面：批次进度条、每篇状态（排队/生成中/门禁通过/门禁拦截/失败/高相似）、单篇重试按钮、批次终止按钮。
- 发布仍是人工，本期不做自动分发。

### 5.8 质量门禁

**代码层**（快，先跑）：机构名白名单（只允许竞品库+客户品牌中的实体名出现）、元话语/占位符检测（"作为AI""以下是""【】"残留）、禁用词（包过/保录取/第一/最好等，沿用 content-plan 禁止事项）、与近 30 天文章 shingle 重复度、竞品强主张复读检测（对竞品库各实体的强主张清单做匹配）。

**LLM 层**（慢，代码层通过后跑）：事实溯源——文中每个数字/专有主张回溯到简报所引资料要点或公共事实，查无来源的标红；语气检测——拉踩、点名贬损、绝对化承诺。

**输出**：结构化检查报告存 `gate_report_json`，页面展示逐项结果。拦截不自动删文，标记状态交运营决定（放行/AI 修改/弃用）。门禁每次拦截记录留痕（长期自进化的负样本）。

## 7. 决策记录（防走回头路）

1. **为什么取消 stage3 插件改写**：合并+改写把 N 篇压成一条指令是雷同根源；库条目本身可直接消费，省一次 LLM 调用。
2. **为什么合并改成入库比对**：比对是"认亲"，颗粒度由最好的一次抽取决定；合并是"平均"，信息只减不增。
3. **为什么段落写法从引用情报来而不是让 LLM 自由发挥**：库里的模式被引用行为验证过；LLM 无约束时收敛到自己的高频套路，批量下比模式轮换更雷同。保留 10-15% 自由槽位作为探索。
4. **为什么写法库要候选/生效两区**：真 playbook 必然跨文章复现（证据计数≥2 晋升），一次性怪招停在候选区，防库膨胀。
5. **为什么缺口要分诊**：对搜不到的缺口反复检索只会捞回内容农场和投放垃圾；"需客户提供"的缺口检索无解。
6. **为什么检索轮数封顶两轮**：第一轮找不到的第三轮也找不到，边际收益归零、污染风险上升。
7. **为什么竞品自述要标记且强主张禁止复读**：竞品联网资料=竞品营销物料，客观转述=免费帮竞品做 GEO（有真实案例）。
8. **为什么多样性用机械组合抽样**：组合空间可计算、可约束、可复现；"请写得多样"不可验证。
9. **为什么不用向量检索/图数据库**：库规模几十到几百条，标签过滤+LLM 全量判断足够；溯源关系查询只有一跳，关系表即图。升级阈值见长期文档。
10. **为什么修改链上下文只取本链**：跨文章上下文是内容互相污染和 token 浪费的来源；链内上下文才对应运营的真实意图。
11. **为什么不拉踩、不点名贬损**：激进投放虽有引用效果（有实例），但涉嫌对真实机构的诽谤且需 cloaking 遮掩；合规观察体同样被引用（有实例）。
12. **为什么 scope/status/valid_until 字段现在就建**：字段成本为零，事后补要迁移数据；长期的行业隔离、条目生命周期、时效降级全依赖它们。

## 9. 风险与回滚

- 每 Phase 独立分支/提交，云端部署走 `git pull --ff-only`，出问题回退到上一提交。
- 数据兼容：新库文件全部是新增路径，不覆盖现有 `latest_injection.md` 等产物；SQLite 加列用 `ALTER TABLE` 且新列可空，旧记录不迁移（`parent_id` 空 = 旧线性记录，UI 兼容展示）。
- 旧引用情报插件在 Phase 2b 上线前保持可用，切换后保留只读展示一个版本周期再删。
- 不改动：爬虫链路、本地 worker、当日整理、记录库、提及识别。
