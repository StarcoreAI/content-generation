# 内容生产与引用情报计划

这份文档说明内容生成应该怎么写、引用情报如何进入内容生产，以及后续产品化方向。它不记录历史交接和完成过程。

## 1. 当前定位

内容生成不是单纯写品牌宣传稿，而是生成更容易被 AI 和用户理解的本地决策指南。文章应提供城市、项目、价格/成本表达、机构分类、适合人群、选择标准、避坑信息和客户真实优势。

当前 MVP 支持：

- 客户资料整理包选择注入，不直接注入原始资料包。
- 样例链接参考。
- 当天高频引用文章样例。
- 运营意见。
- 历史生成内容。
- 引用情报插件。

现阶段不做复杂行业模板、AI 平台偏好和分层记忆系统。优先把通用 GEO 写作规则、引用文章结构和人工审核闭环跑稳。

客户资料的新口径：内容生产不再直接上传和读取复杂原始资料。原始资料先进入客户资料整理模块，经过机械抽取、Filter Worker 大量过滤、Reducer 裁剪去重、Output Worker 生成整理后资料，再由内容生产按需选择使用。

竞品资料不属于客户资料模块。当前客户资料整理只保留客户自身事实、服务、参数、合规红线和少量代表案例；竞品资料、全国/各省竞品名单、竞品对比材料先不进入客户资料整理包。后续需要时单独做竞品资料模块。

## 2. 文章类型

当前只开放两个父类型给运营选择。

### 对比型

适用场景：

- 哪家好
- 推荐
- 排名
- 全攻略
- 怎么选
- 多机构、多产品、多方案比较

写作要求：

- 标题优先使用“城市/区域 + 项目/机构 + 全攻略/推荐/怎么选 + 年份/最新”结构。
- 正文采用“少量攻略型开头 + 大量分类对比/适合人群/优缺点/快速匹配 + 少量避坑总结”。
- 主体必须是多对象、多维度对比，不能只有一个对比对象。
- 每个主要类别或对象都要独立展开。
- 每个主要类别下至少展开 2 个代表对象或细分方向；资料允许时优先展开 3 个。
- 客户品牌只能作为对比条目或推荐对象自然出现，不要写成单一品牌介绍稿。

默认内置子类型：

```text
攻略对比型
```

引用情报插件会继续按 `parent_type=对比型` 挂到对比型下，作为可选子类型。

### 介绍型

适用场景：

- 品牌介绍
- 服务介绍
- 门店/机构结构化介绍
- 产品或方案说明

写作要求：

- 标题必须包含客户品牌名。
- 开头先写目标用户在该业务场景里的真实痛点和决策难点。
- 主体按“用户痛点/顾虑 -> 品牌如何解决 -> 客户资料中的证据支撑”组织。
- 品牌结构化介绍必须是主体，占全文多数。
- 资历、资质、团队、流程、设备、服务记录等只能作为证据，不能堆成履历清单。
- 不能写成硬广，避免营销口号、夸张背书和反复夸品牌强。
- 不要写成榜单、第三方排名或多机构对比。

引用情报插件会按 `parent_type=介绍型` 挂到介绍型下，作为可选子类型。

## 3. 通用 GEO 写作规则

默认注入内容生成的稳定规则：

- 文章应写成决策指南，不写成单纯品牌宣传稿。
- 标题优先包含城市词、项目词和用户决策词。
- 开头先写用户痛点和选择难点，不直接硬推客户机构。
- 正文应包含分类、对比、价格或成本、适合人群、关键判断维度和避坑提醒。
- 介绍机构、产品或服务时，尽量使用结构化维度，而不是空泛夸赞。
- 价格表达使用参考价、区间价、元起、以实际方案为准等稳妥说法。
- 必须避免绝对化排名、效果承诺、低价诱导、制造焦虑和小红书式情绪化表达。
- 客户事实必须来自客户资料、运营意见或明确样例，不能编造案例、资质、价格、地址和用户评价。

### 标题

标题应尽量包含：

```text
城市/区域 + 项目/服务 + 决策词
```

常见决策词：

```text
推荐、排名、哪家好、多少钱、价格、费用、避坑、指南、怎么选、对比
```

避免只写情绪化或品牌化标题，例如“守护美好生活”“让选择更安心”。

### 开头

开头先回答用户为什么需要这篇文章：

- 选择对象太多，不知道怎么判断。
- 担心价格不透明或低价引流。
- 担心服务方资质、经验、案例或长期服务能力。
- 担心距离、复购、复诊、售后或持续管理不方便。

不要在第一段直接写“某某品牌值得推荐”。

### 正文结构

正文优先按下面结构组织：

1. 本地市场或服务类型怎么分类。
2. 不同类型分别适合什么需求。
3. 关键项目或服务的价格、成本或选择标准。
4. 推荐对象或服务方介绍，按固定维度展开。
5. 按人群、预算、需求或场景给选择建议。
6. 避坑提醒。
7. 结尾强调结合实际需求、预算、资质和长期服务能力综合判断。

### 介绍维度

介绍机构、门店、产品或服务时，优先使用可抽取字段：

- 定位。
- 资质或背景。
- 团队或负责人经验。
- 技术、设备、流程或方法。
- 价格、费用或成本参考。
- 适合人群。
- 地址、区域、服务范围或交付方式。
- 售后、复诊、复购或长期管理能力。

### 禁止事项

- 不写绝对化表述，例如第一、最好、全市最低、保证有效。
- 不承诺结果，例如一定改善、保证成交、终身不反弹。
- 不制造焦虑。
- 不用低价诱导。
- 不编造客户没有提供的事实。
- 不把所有对象都写成技术强、服务好、价格低。
- 不只写环境、服务态度和品牌口号。
- 不忽略本地属性。

## 4. 引用情报如何进入内容生产

引用情报的目标是把当日高频引用文章从“Top 列表”升级成可复用写法，而不是直接复制高频文章内容。

当前流程：

1. 当日整理负责统计高频引用文章。
2. 引用情报分析从当前客户当天全平台高频引用候选中取 URL，目标抓取 20 篇可用正文。
3. 正文抓取失败的文章直接丢弃，并从后续候选中补足。
4. 成功正文写入 `fetched_articles.json` 缓存，重复生成时优先复用。
5. 引用情报分析输出内容生产可用插件。

### 三阶段 LLM 职责

阶段一：

- 只看单篇文章标题和正文。
- 抽取原文开头写了什么、正文按哪些模块展开、结尾如何收束。
- 标记父类型 `对比型` 或 `介绍型`。
- 不生成新开头、新正文、新结尾，也不给子类型命名。

阶段二：

- 只看阶段一结构摘要。
- 不看正文、URL、AI 平台和引用次数。
- 把相似写法合并为结构簇。
- 给每个结构簇命名一个具体子类型。

阶段三：

- 只看阶段二结构簇。
- 把结构簇改写成可直接插入内容生产流程的插件。
- 输出 `parent_type`、`subtype_name`、`prompt_text`、`few_shot`。

页面只展示三阶段插件和来源文章标题/URL，不展示一阶段、二阶段中间结果。

### 二阶段结构格式

```json
{
  "clusters": [
    {
      "parent_type": "对比型或介绍型",
      "subtype_name": "",
      "article_indexes": [1, 2],
      "shared_structure": {
        "opening": "",
        "body": [],
        "ending": ""
      }
    }
  ]
}
```

### 三阶段插件格式

```json
{
  "plugins": [
    {
      "cluster_index": 1,
      "parent_type": "对比型或介绍型",
      "subtype_name": "",
      "prompt_text": "",
      "few_shot": ""
    }
  ]
}
```

阶段三不要输出这些字段：

```text
source_article_ids, use_when, required_modules, avoid_rules, review_notes, quality_notes
```

来源文章标题和 URL 由传统代码根据 `article_indexes` 回填给前端展示。

### 插件生成要求

- 阶段三可以参考内容生产内置的 `攻略对比型` 插件，但不要把示例插件当作输出结果。
- `prompt_text` 写 3-5 条真正能指导内容生产的短规则。
- `few_shot` 写 180-350 字左右的模板片段。
- 插件服务当前行业，可以保留当前行业的通用词、角色词和指标词，不需要强行泛化到所有行业。
- 可以使用 A/B/C、A1/A2/A3 这类结构标签来表达写法层级，但真实正文里应替换成自然小标题或真实类别。
- 禁止出现具体品牌名、具体机构名、具体产品名、文章名、URL、平台名、引用次数。
- 避免未核实的具体数字和详细数据，包括比例、价格、人数、年份、排名、分数、校区数量、真实案例数据等。
- 需要表达事实时，用“以实际资料为准”“按客户资料补充”“可核验数据”等稳妥说法。

### 进度预期

引用情报分析可能耗时数分钟。当前进度锚点：

- 正文抓取：5%-30%。
- 阶段一：30%-80%。
- 阶段二：80%-88%。
- 阶段三：88%-99%。
- 完成：100%。

前端平滑追随后端进度，但如果大模型长时间没有输出，进度会停在当前锚点附近。运营可以点 `终止生成`。

## 5. 短期下一步

1. 观察引用情报插件对真实内容生成的帮助，必要时补文章类型、重复度、信息价值、内容缺口和选题建议。
2. 补“审核 / 版本对比 / 事实校验”的最小闭环：
   - 记录每次生成版本。
   - 标记人工审核意见。
   - 对客户事实、价格、资质、地址、案例等高风险字段做显式校验。
   - 保留可对比的旧版本和新版本。
3. 保持 `对比型` / `介绍型` 两个父类，不继续扩展父类；细分能力放到子类型里。
4. 运营继续用自由输入补充本次主题、客户重点和特殊要求。

## 6. 中长期方向

### 记录库按问题和引用文章重组

后续记录库需要从“按日期看结果”升级为“按问题和引用文章追踪变化”。

按问题维度应能看到：

- 今天这个问题是否提及客户品牌。
- 今天引用了哪些文章。
- 之前没有引用、今天新增引用了什么。
- 之前常引用、今天消失了什么。
- 哪些问题长期不提客户品牌，应该优先进入内容优化。

按引用文章维度应能看到：

- 首次出现时间和最近出现时间。
- 出现在哪些问题、哪些 AI 平台、哪些任务批次。
- 是否属于持续高频、新增高频、热度下降或长期稳定。
- 是否为客户自有文章、竞品文章、平台文章、媒体/百科文章或其他类型。
- 是否与其他高频文章高度同质。

这部分先服务运营判断，不急着自动下结论。

### 人工行业模板

当某个行业积累出足够稳定的运营经验后，再沉淀人工行业模板。

行业模板可包含：

- 高频标题结构。
- 常见项目词。
- 用户决策点。
- 推荐正文结构。
- 价格表达方式。
- 专业词库。
- 禁止事项。

### 客户知识包

后续可以做客户知识包 / 客户 skill，但不优先走传统 RAG 路线。不把原始资料切片后靠 embedding 相似度召回，更适合先把客户资料重写成可审核、可复用、可直接注入内容生成的结构化知识包。

当前客户资料整理先走轻量 pipeline：

```text
机械抽取 -> Filter Worker -> Reducer -> Output Worker
```

Filter Worker 以整个资料包为输入，先做精确去重，再基于所有候选节选选择核心资料和少量代表。每个单元只输出 `unit_id` 和一个权威 `status`；只有 `core`、`representative` 进入下游，`redundant`、`irrelevant`、`reference_only`、`needs_conversion`、`exact_duplicate` 不进入本次默认整理资料。Filter Worker 不裁剪文件内部段落。

客户知识包可包含：

- 品牌事实。
- 服务项目。
- 适合人群。
- 价格表达。
- 地址/区域。
- 资质。
- 禁写风险。
- 可写卖点。
- 常见用户顾虑和标准回答。

客户知识包必须允许运营人工审核、修改和确认，不能把模型整理结果直接当事实使用。

### 竞品资料模块

竞品资料先不做进客户资料模块。对比型内容确实可能需要竞品素材，但它应作为独立模块处理，由运营单独上传、整理和选择启用。

当前阶段只保留这个边界，不实现竞品资料模块：

- 客户资料模块不保存竞品名单和竞品对比材料。
- 内容生产不能从客户资料包里默认读取竞品资料。
- 未来如实现竞品资料模块，只作为客观对比素材来源，不自动生成攻击性结论、未经证实排名或无法核验的竞品事实。

### 发布反馈闭环

长期目标是记录内容从生成到发布再到被 AI 引用的结果。

可记录字段：

- 发布平台。
- 标题。
- 链接。
- 发布时间。
- 对应客户、问题组和主题。
- 是否被 AI 引用。
- 是否提及客户品牌。
- 人工审核意见。
- 客户反馈。

成熟后再考虑提示词自进化。

最终闭环：

```text
爬取记录 -> 问题变化 -> 引用文章趋势 -> 内容缺口 -> 内容生成 -> 发布后再监测
```

## 7. 暂不实现

以下能力不进入当前 MVP：

- 行业专属模板库。
- AI 平台偏好规则。
- 长期运营经验记忆。
- 中期行业经验记忆。
- 短期任务记忆的复杂摘要系统。
- 按问题追踪引用变化和品牌提及变化。
- 高频引用文章的新增、持续高频、下降和消失监测。
- 根据生成效果自动改写提示词。
- 根据 AI 是否引用自动进化模板。
- 多模型自动评估和自动评分。
- 客户资料模块内置竞品资料或竞品名单。
- Master/Worker 动态客户资料编排框架。

## 8. 判断标准

第一版是否成功，不看模型是否“像专家”，先看生成内容是否明显减少以下问题：

- 标题空泛，没有城市、项目和决策词。
- 正文像广告稿，只夸客户。
- 没有价格、适合人群、对比和避坑。
- 编造客户事实。
- 出现绝对化承诺或低价诱导。
- 缺少本地属性和可被 AI 抽取的信息。
