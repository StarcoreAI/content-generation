# 内容生产当前边界

更新时间：2026-08-04

## 正式链路

`app.run_content_generation(...)` 是网页单篇、批量任务和 CLI 共用的入口：

```text
运营选择客户、问题组、Query 与文章类型
→ 运营显式选择客户资料、内容上传资料和竞品分节
→ 按行业与介绍型/对比型选择路线
→ 单阶段写作 LLM
→ 质量门禁提醒
→ SQLite 入库
```

没有简报 LLM、候选/active 路线状态、随机竞品池或旧插件链路。行业路线只提供组织方式，不是可复制的事实模板。

## 类型与资料边界

- **介绍型**：必须有客户资料；标题包含客户品牌。内容上传资料仅在勾选时使用。开头围绕 Query 像熟悉问题的人自然交谈，先接住困惑或场景，再进入客户事实主线。
- **对比型**：必须有客户资料与至少两家运营明确选择的竞品；按 Query 提炼比较维度，客观描述，不拉踩、不编造竞品事实。开头先帮助读者建立比较语境，再进入后续比较维度。
- 两类文章均要求标题后至首个二级标题前不少于 600 个汉字，不设上限；可以自由扩充必要的常识、判断过程和共鸣，但不得把通用扩充写成任何客户或竞品的专属事实。
- 客户资料、竞品资料和内容上传资料互相独立；不得暗中扩大输入或混入未选择资料。
- 当前 Query 的场景词只作轻量提示，不应堆词、偏题或取代事实。

## 引用情报与路线

引用情报按一个客户、一个合同 AI 平台运行；分析范围默认是所选问题组的全部问题，运营可改选单题。任务在后台执行并由前端轮询状态。系统从该范围内的实际引用记录选择文章、分析后沉淀介绍型或对比型行业路线；正文抓取和单篇分析按 URL 缓存。路线创建、删除均立即入库。

## 不在范围内

不建设平台偏好矩阵、运营经验库、自动权重优化、提示词自改写、反思任务或向量/RAG 升级。发布与运营复盘仍由人工决定。

## 本轮已确认：引用情报与竞品资料提速（2026-08-02）

- 引用情报分析保持“每题高频第一篇 + 第 2–5 名按引用次数加权抽一篇”的选文口径；新增按 URL 的正文缓存、按 URL + 正文哈希的单篇分析缓存。缓存只跳过重复抓取和重复单篇分析，不改变本次选文或最终写法库合并。
- 竞品资料保持“当前日期、问题组、AI 平台、任务范围内，按 URL 去重后取引用次数前 12 篇不同文章”的口径；保留现有正文缓存，并新增 URL + 正文哈希的竞品事实提取缓存。新文章或正文变化才再次调用模型。
- 首次运行的抓取最多 3 路并发；浏览器兜底抓取最多 1 路；引用情报单篇分析与竞品事实提取共用最多 2 路的后台模型并发闸门。最终写法库合并仍串行，竞品 Markdown 合并仍本地执行。
- 写法库合并由模型判断：去掉实体、事实数字和 Query 后，若两种写法可以自然写成同一篇文章，只是措辞不同则合并；场景不同视为读者感知差异，默认不合并。保留跨客户复用与不含具体来源事实的边界。
- 批量内容生产的 401 鉴权问题单独处理：后台线程必须按创建任务的运营账号读取其个人模型配置，不能退回全局 token，也不能把 token 返回给前端。
- 内容生产篇数固定为 1、2、3 篇；批量仍按顺序生成，每篇沿用创建任务的运营账号模型配置，并将同一配置用于正文生成和质量门禁。
