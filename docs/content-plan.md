# 内容生产与引用情报计划

这份文档说明内容生成应该怎么写、引用情报如何进入内容生产，以及后续产品化方向。它不记录历史交接和完成过程。

内容链路正在按重构文档改造：施工规格见 `docs/content-refactor-short-term.md`，远期方向见 `docs/content-refactor-long-term.md`。本文档的写作规则（第 2、3 节）继续有效，作为写作 LLM 的规则来源；与重构文档冲突的流程描述以重构文档为准。

## 1. 当前定位

内容生成不是单纯写品牌宣传稿，而是生成更容易被 AI 和用户理解的本地决策指南。文章应提供城市、项目、价格/成本表达、机构分类、适合人群、选择标准、避坑信息和客户真实优势。

当前 MVP 支持：

- 内容生产独立资料上传和解析注入，不直接读取客户资料解析模块的上传资料。
- 样例链接参考。
- 当天高频引用文章样例。
- 运营意见。
- 历史生成内容。
- 引用情报插件。
- 父类型和子类型选择；生成结果展示调用模型、父类型、子类型、资料数量和样例数量。

AI 平台偏好和记忆自进化按 `docs/content-refactor-long-term.md` 的顺序推进（先归因、后微调）；行业维度通过写法库的行业作用域实现，不做人工行业模板。优先把通用 GEO 写作规则、结构化中间层和人工审核闭环跑稳。

资料来源的新口径：内容生产上传资料和客户资料解析上传资料是两套独立系统。内容生产页上传的资料会即时解析并参与文章生成，可逐份关闭；客户资料解析模块产出的 `latest_injection.md`、`latest_web_supplement.md` 已在内容生产页提供显式开关，运营可选择使用或不使用。

竞品资料不属于客户资料模块。当前已有独立竞品资料解析模块，上传资料和联网资料按真实竞品名称分组整理；内容生产如需使用竞品资料，应由运营显式放入内容生产资料或后续通过独立选择入口启用。

## 2. 文章类型

当前只开放两个父类型给运营选择。

### 对比型

适用场景：

- 哪家好
- 推荐
- 排名
- 全攻略
- 怎么选
- 多机构、多产品、多方案比较

写作要求：

- 标题优先使用“城市/区域 + 项目/机构 + 全攻略/推荐/怎么选 + 年份/最新”结构。
- 正文采用“少量攻略型开头 + 大量分类对比/适合人群/优缺点/快速匹配 + 少量避坑总结”。
- 主体必须是多对象、多维度对比，不能只有一个对比对象。
- 每个主要类别或对象都要独立展开。
- 每个主要类别下至少展开 2 个代表对象或细分方向；资料允许时优先展开 3 个。
- 客户品牌只能作为对比条目或推荐对象自然出现，不要写成单一品牌介绍稿。
- 竞品名称必须使用真实品牌名、机构名、门店名或公司名，禁止用 A/B/C、竞品1、竞品2 等占位名称替代。
- 不拉踩其他竞品，不通过贬低竞品突出客户品牌；要客观说明其他竞品的优点、适合人群和限制，方便用户选择。
- 可以把客户品牌放在对比对象最前面，让用户优先了解客户品牌，但后续竞品也要保持客观、完整、可核验。

默认内置子类型：

```text
攻略对比型
```

引用情报插件会继续按 `parent_type=对比型` 挂到对比型下，作为可选子类型。

### 介绍型

适用场景：

- 品牌介绍
- 服务介绍
- 门店/机构结构化介绍
- 产品或方案说明

写作要求：

- 标题必须包含客户品牌名。
- 开头先写目标用户在该业务场景里的真实痛点和决策难点。
- 主体按“用户痛点/顾虑 -> 品牌如何解决 -> 客户资料中的证据支撑”组织。
- 品牌结构化介绍必须是主体，占全文多数。
- 资历、资质、团队、流程、设备、服务记录等只能作为证据，不能堆成履历清单。
- 不能写成硬广，避免营销口号、夸张背书和反复夸品牌强。
- 不要写成榜单、第三方排名或多机构对比。

引用情报插件会按 `parent_type=介绍型` 挂到介绍型下，作为可选子类型。

## 3. 通用 GEO 写作规则

默认注入内容生成的稳定规则：

- 文章应写成决策指南，不写成单纯品牌宣传稿。
- 标题优先包含城市词、项目词和用户决策词。
- 开头先写用户痛点和选择难点，不直接硬推客户机构。
- 正文应包含分类、对比、价格或成本、适合人群、关键判断维度和避坑提醒。
- 介绍机构、产品或服务时，尽量使用结构化维度，而不是空泛夸赞。
- 价格表达使用参考价、区间价、元起、以实际方案为准等稳妥说法。
- 必须避免绝对化排名、效果承诺、低价诱导、制造焦虑和小红书式情绪化表达。
- 客户事实必须来自内容生产资料、客户资料、运营意见或明确样例，不能编造案例、资质、价格、地址和用户评价。
- 竞品事实必须来自竞品资料、运营意见或可追溯公开来源，不能编造排名、效果、价格、案例或用户评价。
- 竞品自述类信息（通过率数字、"唯一/第一"类主张、荣誉榜单）不得作为客观事实转述；只能带"品牌自述、以官方发布为准"话术出现，或直接不写。复读竞品强主张等于免费帮竞品做 GEO。
- FAQ 段和对比表是标准可选模块：FAQ 问题优先取自该客户问题组的用户原话句式；对比表用于分人群/分维度建议。是否携带由抽样决定，不要求每篇都有。

### 标题

标题应尽量包含：

```text
城市/区域 + 项目/服务 + 决策词
```

常见决策词：

```text
推荐、排名、哪家好、多少钱、价格、费用、避坑、指南、怎么选、对比
```

避免只写情绪化或品牌化标题，例如“守护美好生活”“让选择更安心”。

### 开头

开头先回答用户为什么需要这篇文章：

- 选择对象太多，不知道怎么判断。
- 担心价格不透明或低价引流。
- 担心服务方资质、经验、案例或长期服务能力。
- 担心距离、复购、复诊、售后或持续管理不方便。

不要在第一段直接写“某某品牌值得推荐”。

### 正文结构

正文优先按下面结构组织：

1. 本地市场或服务类型怎么分类。
2. 不同类型分别适合什么需求。
3. 关键项目或服务的价格、成本或选择标准。
4. 推荐对象或服务方介绍，按固定维度展开。
5. 按人群、预算、需求或场景给选择建议。
6. 避坑提醒。
7. 结尾强调结合实际需求、预算、资质和长期服务能力综合判断。

### 介绍维度

介绍机构、门店、产品或服务时，优先使用可抽取字段：

- 定位。
- 资质或背景。
- 团队或负责人经验。
- 技术、设备、流程或方法。
- 价格、费用或成本参考。
- 适合人群。
- 地址、区域、服务范围或交付方式。
- 售后、复诊、复购或长期管理能力。

### 禁止事项

- 不写绝对化表述，例如第一、最好、全市最低、保证有效。
- 不承诺结果，例如一定改善、保证成交、终身不反弹。
- 不制造焦虑。
- 不用低价诱导。
- 不编造客户没有提供的事实。
- 不把所有对象都写成技术强、服务好、价格低。
- 不只写环境、服务态度和品牌口号。
- 不忽略本地属性。

## 4. 引用情报如何进入内容生产

引用情报的目标是把当日高频引用文章从“Top 列表”升级成可复用写法，而不是直接复制高频文章内容。

重要认知（2026-07 人工分析五篇高频引用文章的结论）：高频引用文章池主要是我方与竞品的 GEO 投放战场，写法 playbook 已收敛。引用情报学的是"什么形状的文章会被引用"，不是内容本身；低质文章（如标题写对比、正文只吹一家）也会被高频引用，分析前必须过滤。

目标流程（施工规格见 `docs/content-refactor-short-term.md` 5.1 节）：

1. 过滤与定性：一稿多发归并、低质过滤、投放定性和风险手段标记。
2. 逐篇抽取：每篇产出"文章解剖卡"（骨架 + 段落模式候选 + 引用友好特征），每篇限额。
3. 入库比对：与写法库（含候选区）判重，同套路加证据计数，新套路建候选条目。
4. 候选条目在来源独立的文章中复现 ≥2 次或运营批准后晋升生效；抽样只用生效条目。

不再把结构簇改写成 `prompt_text + few_shot` 插件；写法库条目直接作为策划简报 LLM 的输入。旧三阶段流水线在重构 Phase 2a/2b 完成前继续运行，完成后删除。

## 5. 短期下一步

短期施工全部收敛到 `docs/content-refactor-short-term.md`。客户资料八分类、客户联网扩展三类素材、内容生产资料包显式开关、竞品资料 prompt 收紧已经完成；下一步先做内容生产接入验证，再进入竞品实体库、写法库与引用情报流水线、策划简报+写作两级、版本修改链、质量门禁和一键批量生成。

本文档层面保留的约束：

1. 继续只保留 `对比型` / `介绍型` 两个父类；细分能力放到子类型里，不扩展新的父类。
2. 发布登记表（长期文档第 2 节）建议随短期一并做，历史发布记录不可事后补。

## 6. 中长期方向

中长期整体规划（分发、观测归因、平台微调、记忆与自进化）见 `docs/content-refactor-long-term.md`。下面保留的小节是与本文档主题直接相关的补充说明。

### 记录库按问题和引用文章重组

后续记录库需要从“按日期看结果”升级为“按问题和引用文章追踪变化”。

按问题维度应能看到：

- 今天这个问题是否提及客户品牌。
- 今天引用了哪些文章。
- 之前没有引用、今天新增引用了什么。
- 之前常引用、今天消失了什么。
- 哪些问题长期不提客户品牌，应该优先进入内容优化。

按引用文章维度应能看到：

- 首次出现时间和最近出现时间。
- 出现在哪些问题、哪些 AI 平台、哪些任务批次。
- 是否属于持续高频、新增高频、热度下降或长期稳定。
- 是否为客户自有文章、竞品文章、平台文章、媒体/百科文章或其他类型。
- 是否与其他高频文章高度同质。

这部分先服务运营判断，不急着自动下结论。

### 客户资料包

短期不新建逐条客户知识库，也不把资料整理结果直接当事实使用。客户资料解析模块继续保留现有轻量 pipeline：

```text
机械抽取 -> Filter Worker -> Reducer -> Output Worker
```

它的终点仍是 `latest_injection.md` 和 `latest_web_supplement.md` 这类资料包。内容生产页已提供两个资料包的显式使用开关。哪些信息必须覆盖、哪些角度适合展开，放到内容生产一阶段的信息整理 LLM 里按单篇任务生成；明显矛盾、夸大、无依据的内容放到质量门禁处理。

### 竞品资料模块

竞品资料保持独立模块，不进入客户资料模块。当前上传解析和联网整理 prompt 已要求真实竞品名分组、来源 URL/来源性质、宣传主张集中记录、疑似投放不采信、主观负面只作内部备注。目标形态仍是从 Markdown 升级为竞品实体库：按实体结构化条目、每字段带来源类型、强主张清单（禁止放大）、安全描述、冲突标记、置顶/拉黑控制。数据模型见短期文档 4.3 节。

边界不变：只作客观对比素材来源，不自动生成攻击性结论、未经证实排名或无法核验的竞品事实；内容生产使用竞品资料必须经运营可控的选择机制（置顶/拉黑）。

### 发布反馈闭环

见 `docs/content-refactor-long-term.md` 第 2-4 节（发布登记表、归因匹配、成绩单报表）。最终闭环不变：

```text
爬取记录 -> 问题变化 -> 引用文章趋势 -> 内容缺口 -> 内容生成 -> 发布后再监测
```

## 7. 暂不实现

以下能力不进入短期施工（其中一部分已列入长期规划，见长期文档；另一部分明确不做）：

- AI 平台偏好规则（长期：归因数据积累后做偏好矩阵）。
- 运营经验库与模块权重自进化（长期：老虎机 + 反思任务）。
- 按问题追踪引用变化和品牌提及变化、高频引用文章趋势监测（长期：归因与记录库重组）。
- 无人审核的提示词自动改写（不做：进化只发生在库条目权重和运营批准的新条目两个受控层面）。
- 多模型自动评估和自动评分（不做）。
- 客户资料模块内置竞品资料或竞品名单（不做，竞品保持独立模块）。
- Master/Worker 动态客户资料编排框架（不做）。
- 复杂 RAG、向量检索、图数据库（不做，升级阈值见长期文档 6.4 节）。

## 8. 判断标准

第一版是否成功，不看模型是否“像专家”，先看生成内容是否明显减少以下问题：

- 标题空泛，没有城市、项目和决策词。
- 正文像广告稿，只夸客户。
- 没有价格、适合人群、对比和避坑。
- 编造客户事实。
- 出现绝对化承诺或低价诱导。
- 缺少本地属性和可被 AI 抽取的信息。
