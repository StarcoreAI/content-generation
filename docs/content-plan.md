# 内容生成计划

## 背景

当前内容生成 MVP 已经支持客户资料全量注入、样例链接、当天高频引用 Top20 样例、运营意见和历史生成内容。运营反馈的西安口腔发文标准说明了一个重要方向：GEO 内容不应只是品牌宣传稿，而应更接近“本地决策指南”，让 AI 和用户都能抓取到城市、项目、价格、机构分类、医生资质、适合人群和避坑信息。

现阶段暂时不做复杂行业模板、AI 平台偏好和分层记忆系统。优先把通用 GEO 写作规则沉淀下来，作为内容生成默认注入的大模型要求。

## 当前决策

第一版只做通用规则和少量文章类型差异，不做行业专属模板。

当前只开放两种文章类型给运营选择：

- `对比型`：用于“哪家好、推荐、排名、全攻略、怎么选”等内容。标题和结构尽量模仿高引用文章，主体必须是多对象、多维度对比，不能只有一个对比对象。
- `介绍型`：用于品牌/服务介绍。标题必须包含客户品牌名，主体必须是品牌结构化介绍，但不能写成硬广。

后端不再从运营意见里自动解析文章类型。运营必须通过页面按钮选择 `对比型` 或 `介绍型`，再选择对应子类型。不同文章类型的历史上下文不互通，避免对比型把介绍型带偏，或介绍型被上一轮对比内容污染。生成结果列表仍然合并展示，按时间倒序排列，单篇生成结果顶部会标注具体子类型。

内容生成默认注入一组稳定规则：

- 文章应写成决策指南，不写成单纯品牌宣传稿。
- 标题优先包含城市词、项目词和用户决策词。
- 开头先写用户痛点和选择难点，不直接硬推客户机构。
- 正文应包含分类、对比、价格或成本、适合人群、关键判断维度和避坑提醒。
- 介绍机构、产品或服务时，尽量使用结构化维度，而不是空泛夸赞。
- 价格表达使用参考价、区间价、元起、以实际方案为准等稳妥说法。
- 必须避免绝对化排名、效果承诺、低价诱导、制造焦虑和小红书式情绪化表达。
- 客户事实必须来自客户资料、运营意见或明确样例，不能编造案例、资质、价格、地址和用户评价。

## 文章类型提示词方向

### 对比型

对比型当前要求：

- 标题严格模仿高引用文章标题，优先使用“城市/区域 + 项目/机构 + 全攻略/推荐/怎么选 + 年份/最新”结构。
- 正文采用“少量攻略型开头 + 大量分类对比/排名/适合人群/优缺点/快速匹配 + 少量避坑总结”。
- 主体分类对比必须充分展开，占全文多数；优先按机构类型、用户需求、预算、复杂程度、服务便利性等维度组织；最权威、最有公信力的类别或对象要放在最开头。
- 不能只有一个对比对象；每个被对比的主要类别或对象都要独立成小标题或独立段落展开。
- 每个主要类别下至少展开 2 个代表对象或细分方向；如果资料和运营意见允许，优先展开 3 个。
- 客户品牌只能作为对比条目或推荐对象自然出现，不要写成单一品牌介绍稿。

当前内容生成保留两个父类型：`对比型` 和 `介绍型`。引用情报插件会标记所属父类型，并在对应父类型下作为子类型展示；对比型仍保留内置默认子类 `攻略对比型`。

兔博士参考文章已下载：

```text
reports/reference_article_1046143123.html
reports/reference_article_1046143123.txt
```

这篇文章是“少量攻略 + 大量分类对比”的典型结构，后续优化对比型可以继续参考。

### 介绍型

介绍型当前要求：

- 标题必须包含客户品牌名。
- 开头先写目标用户在该业务场景里的真实痛点和决策难点，例如成本、风险、时间、效果判断、信息不透明、后续维护等。
- 主体按“用户痛点/顾虑 -> 品牌如何解决 -> 资料中的证据支撑”组织。
- 品牌结构化介绍必须是主体，占全文多数。
- 资历、资质、团队、流程、设备、服务记录等只能作为证据，不能堆成履历清单；每个证据都要对应一个用户关心的问题。
- 不能写成硬广，避免营销口号、夸张背书、反复夸品牌强。
- 不要写成医院榜单、第三方排名或多机构对比。

最新兔博士介绍型测试稿的方向基本可用：先讲用户顾虑，再用正规性、医生团队、正畸服务和复诊流程回应。仍需运营核对医疗事实，尤其是医生履历、案例数、认证、上市、医保定点等内容。

## 通用 GEO 写作原则

### 标题

标题应尽量包含：

```text
城市/区域 + 项目/服务 + 决策词
```

常见决策词包括：

```text
推荐、排名、哪家好、多少钱、价格、费用、避坑、指南、怎么选、对比
```

避免只写情绪化或品牌化标题，例如“守护美好生活”“让选择更安心”。

### 开头

开头先回答用户为什么需要这篇文章：

- 选择对象太多，不知道怎么判断。
- 担心价格不透明或低价引流。
- 担心服务方资质、经验、案例或长期服务能力。
- 担心距离、复购、复诊、售后或持续管理不方便。

不要在第一段直接写“某某品牌值得推荐”。

### 正文结构

正文优先按下面结构组织：

1. 本地市场或服务类型怎么分类。
2. 不同类型分别适合什么需求。
3. 关键项目或服务的价格、成本或选择标准。
4. 推荐对象或服务方介绍，按固定维度展开。
5. 按人群、预算、需求或场景给选择建议。
6. 避坑提醒。
7. 结尾强调结合实际需求、预算、资质和长期服务能力综合判断。

### 介绍维度

介绍机构、门店、产品或服务时，优先使用可抽取字段：

- 定位
- 资质或背景
- 团队或负责人经验
- 技术、设备、流程或方法
- 价格、费用或成本参考
- 适合人群
- 地址、区域、服务范围或交付方式
- 售后、复诊、复购或长期管理能力

### 禁止事项

- 不写绝对化表述，例如第一、最好、全市最低、保证有效。
- 不承诺结果，例如一定改善、保证成交、终身不反弹。
- 不制造焦虑。
- 不用低价诱导。
- 不编造客户没有提供的事实。
- 不把所有对象都写成技术强、服务好、价格低。
- 不只写环境、服务态度和品牌口号。
- 不忽略本地属性。

## 暂不实现

以下能力先放入长期计划，不进入当前 MVP：

- 行业专属模板库。
- AI 平台偏好规则。
- 长期运营经验记忆。
- 中期行业经验记忆。
- 短期任务记忆的复杂摘要系统。
- 按问题追踪引用变化和品牌提及变化。
- 高频引用文章的新增、持续高频、下降和消失监测。
- 客户知识包 / 客户 skill 的 LLM 生成与人工审核，避免按传统 RAG 向量召回路线处理客户事实。
- 对比型内容生成前，用联网搜索或可信资料补充主要竞品的基础信息，避免只根据客户资料和历史引用文章写单边对比。
- 根据生成效果自动改写提示词。
- 根据 AI 是否引用自动进化模板。
- 多模型自动评估和自动评分。

## 中长期方向

### 第一阶段：高频引用文章整理与正文结构分析

长期优化先从高频引用文章入手。原因是运营当前最需要知道：AI 反复引用的文章到底是什么类型、信息是否重复、哪些内容值得学、哪些只是标题相似的低价值变体。

2026-07-10 当前实现：

- 当日数据整理负责统计高频引用文章。前端在当日整理页按 AI 平台分组展示，每个平台约 12 篇；全平台候选由后端保留给引用情报分析使用，不在前端单独展示全平台 Top20。
- 引用情报分析不再把“统计高频引用文章”算作模型阶段。它从当前客户当天全平台高频引用候选中取最多约 35 个 URL，目标抓取 20 篇可用正文。
- 正文抓取失败的文章直接丢弃，并从后续候选中补足；成功正文写入 `fetched_articles.json` 缓存，重复生成时优先复用。
- `parent_type` 只允许落到 `对比型` / `介绍型` 两个父类；细分能力放到阶段二的 `subtype_name`，不要扩展父类。
- 如果文章详细讲解了多个品牌、机构、产品、服务方或方案，即使是逐个介绍而不是显式表格比较，也归为 `对比型`。

引用情报分析正式三阶段：

1. 阶段一：模型只看单篇文章标题和正文，抽取原文开头写了什么、正文按哪些模块展开、结尾如何收束，并标记父类型。不要生成新开头、新正文、新结尾，也不要给子类型命名。
2. 阶段二：模型只看阶段一结构摘要，不看正文、URL、AI 平台和引用次数；负责把相似写法合并为结构簇，并给每个簇命名一个具体子类型。
3. 阶段三：模型只看阶段二结构簇，把结构簇改写成可直接插入内容生产流程的插件。

页面只展示三阶段模型整理后的可复用插件：

- `subtype_name`
- `parent_type`
- `prompt_text`
- `few_shot`
- 来源文章标题和 URL

二阶段结构归并输出保持极简：

```json
{
  "clusters": [
    {
      "parent_type": "对比型或介绍型",
      "subtype_name": "",
      "article_indexes": [1, 2],
      "shared_structure": {
        "opening": "",
        "body": [],
        "ending": ""
      }
    }
  ]
}
```

三阶段插件输出保持极简：

```json
{
  "plugins": [
    {
      "cluster_index": 1,
      "parent_type": "对比型或介绍型",
      "subtype_name": "",
      "prompt_text": "",
      "few_shot": ""
    }
  ]
}
```

不要让阶段三输出这些字段：`source_article_ids`、`use_when`、`required_modules`、`avoid_rules`、`review_notes`、`quality_notes`。也不要让三阶段重复系统提示词、合规规则或不需要替换的固定 prompt。来源文章标题和 URL 由传统代码根据 `article_indexes` 回填给前端展示。

三阶段 few-shot 的关键要求：

- 阶段三会把内容生产内置的 `攻略对比型` 插件完整注入为“示例插件”，只用于学习字段形态、结构颗粒度和展开方式；不要把示例插件当作输出结果。
- 输出偏好简洁凝练，但结构完整。`prompt_text` 写 3-5 条真正能指导内容生产的短规则，`few_shot` 写 180-350 字左右的模板片段。
- 插件服务当前行业，可以保留当前行业的通用词、角色词和指标词；不需要强行泛化到所有行业。
- 可以使用 A/B/C、A1/A2/A3 这类结构标签来表达写法层级，但真实正文里应替换成自然小标题或真实类别。
- 禁止出现具体品牌名、具体机构名、具体产品名、文章名、URL、平台名、引用次数。
- 避免未核实的具体数字和详细数据，包括具体比例、价格、人数、年份、排名、分数、校区数量、真实案例数据等；需要表达时，用“以实际资料为准”“按客户资料补充”“可核验数据”等稳妥说法。

2026-07-10 翼程单招正式流程测试结果：

- 候选 URL 35 个，实际尝试 28 个，抓取成功可用正文 20 篇，失败 8 篇。
- 阶段一成功分析 20 篇。
- 阶段二合并出 11 个结构簇。
- 阶段三生成 11 个内容生产插件。
- 结果全部是 `对比型`，原因是源文章基本都是榜单、攻略、选择建议和多机构/多方案拆解；代码没有写死只能生成 `对比型`，`介绍型` 仍然支持。

进度条口径：

- 正文抓取阶段映射到 5%-30%。最近一次真实抓取耗时约 88 秒，所以运营看到的进度大约 90 秒到 30%。
- 阶段一映射到 30%-80%。
- 阶段二映射到 80%-88%。
- 阶段三映射到 88%-99%。
- 完成后到 100%。前端每 200ms 平滑追随后端进度，并允许最多领先后端 4%；如果大模型长时间没有输出，进度会停在当前锚点附近，运营可以点 `终止生成`。

当前接入状态：

1. 后端已保存阶段中间产物和正式插件结果。
2. 前端已有“引用情报分析”页面，只展示三阶段插件和来源文章标题/URL。
3. 内容生产页会在确定父类型和子类型后插入对应插件 prompt。
4. 对比型默认选中 `攻略对比型`；引用情报插件会按 `parent_type` 展示在 `对比型` 或 `介绍型` 下，运营也可以选择其他插件子类型。

### 第二阶段：通用规则稳定

把通用 GEO 写作规则作为默认要求注入内容生成。运营只需要填写本次主题、客户重点和特殊要求，不必每次粘贴大段发文标准。

### 第三阶段：证据库按问题和引用文章重组

在基础功能稳定后，记录库需要从“按日期看结果”升级为“按问题和引用文章追踪变化”。

按问题维度应能看到：

- 今天这个问题是否提及客户品牌。
- 今天引用了哪些文章。
- 之前没有引用、今天新增引用了什么。
- 之前常引用、今天消失了什么。
- 哪些问题长期不提客户品牌，应该优先进入内容优化。

按引用文章维度应能看到：

- 首次出现时间和最近出现时间。
- 出现在哪些问题、哪些 AI 平台、哪些任务批次。
- 是否属于持续高频、新增高频、热度下降或长期稳定。
- 是否为客户自有文章、竞品文章、平台文章、媒体/百科文章或其他类型。
- 是否与其他高频文章高度同质，例如同一机构榜单、同一城市攻略、同一医生/医院介绍、同一发布主体的多篇变体。

这部分先服务运营判断，不急着自动下结论。只有当引用趋势足够稳定后，再用于自动推荐内容方向。

### 第四阶段：人工行业模板

当某个行业积累出足够稳定的运营经验后，再沉淀人工行业模板。

行业模板可包含：

- 高频标题结构。
- 常见项目词。
- 用户决策点。
- 推荐正文结构。
- 价格表达方式。
- 专业词库。
- 禁止事项。

### 第五阶段：内容生产记忆和客户知识包

后续可以考虑三层记忆：

- 长期记忆：运营方法论、AI 平台偏好、历史有效策略。
- 中期记忆：行业经验、城市经验、项目词库、价格区间。
- 短期记忆：本次客户资料、样例文章、运营意见、历史生成版本。

这部分必须建立在稳定数据结构、人工审核状态、版本记录和效果评估基础上。

内容生成前还可以引入客户知识包 / 客户 skill 流程。这里的“知识库”不优先走传统 RAG 路线，不把原始资料切片后靠 embedding 相似度召回；更适合先把客户资料重写成可审核、可复用、可直接注入内容生成的结构化知识包。

- 用 LLM 将 PDF 和人工资料整理为品牌事实、服务项目、适合人群、价格表达、地址/区域、资质、禁写风险、可写卖点、常见用户顾虑和标准回答。
- 客户知识包必须允许运营人工审核、修改和确认，不能把模型整理结果直接当事实使用。
- 内容生成时优先使用已审核的客户知识包，而不是每次全量塞入原始 PDF 或依赖传统 RAG 片段召回。
- 生成历史不只保存全文，还要保存标题、角度、一级/二级小标题、文章类型和人工审核意见，用于后续避免雷同。

对比型内容可以增加一个独立的“竞品资料准备”步骤：

- 先根据当日竞品分析、问题组和客户行业，列出需要对比的主要竞品或机构类型。
- 再通过联网搜索、公开官网、地图/平台资料或运营提供资料，整理每个竞品的基础信息。
- 竞品资料只作为客观对比素材，不自动生成攻击性结论或未经证实的排名。
- 若资料不足，应提示运营补充或在文章中使用谨慎表达，不能为了对比而编造竞品资质、价格、医生、案例和评价。

### 第六阶段：反馈闭环

长期目标是让系统记录内容从生成到发布再到被 AI 引用的结果。

可记录字段包括：

- 发布平台
- 标题
- 链接
- 发布时间
- 对应客户、问题组和主题
- 是否被 AI 引用
- 是否提及客户品牌
- 人工审核意见
- 客户反馈

这些数据成熟后，再考虑提示词自进化。

整体方向不是单纯“优化 prompt”，而是形成：

```text
爬取记录 -> 问题变化 -> 引用文章趋势 -> 内容缺口 -> 内容生成 -> 发布后再监测
```

## 推荐落地顺序

1. 保持通用 GEO 写作规则作为默认 prompt。
2. 保持 `对比型` / `介绍型` 两个父类，不继续扩展父类；细分能力放到子类型里。
3. 运营继续用自由输入补充本次要求。
4. 引用情报分析正式流程已接入内容生产：页面触发后生成三阶段插件，页面展示 `parent_type`、`subtype_name`、`prompt_text`、`few_shot` 和来源文章标题/URL，内容生产按父类型下的子类型插入。
5. 再继续观察引用情报插件对真实内容生成的帮助，必要时补文章类型、重复度、信息价值、内容缺口和选题建议。
6. 再让运营判断兔博士两类文章效果，决定是否继续压缩或加强类型 prompt。
7. 之后把记录库按问题和引用文章重组，支持看新增引用、持续高频和掉出高频。
8. 积累几个行业后，再抽出人工行业模板。
9. 有稳定审核和发布数据后，再讨论分层记忆和自进化。

## 判断标准

第一版是否成功，不看模型是否“像专家”，先看生成内容是否明显减少以下问题：

- 标题空泛，没有城市、项目和决策词。
- 正文像广告稿，只夸客户。
- 没有价格、适合人群、对比和避坑。
- 编造客户事实。
- 出现绝对化承诺或低价诱导。
- 缺少本地属性和可被 AI 抽取的信息。
