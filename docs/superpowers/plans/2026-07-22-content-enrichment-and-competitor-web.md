## 共同背景（为什么改）

运营反馈两类问题，已完成诊断，根源都在我们自己写的 prompt 规则，不在写法库、不在门禁：

1. **成文是"转述腔"**：文章里"翼升学官网介绍……根据其官网介绍……"满天飞，一看就是 AI 写的。根源：`services/brief_builder.py` 简报 prompt 要求素材池每条都带"其官网介绍/公开页面显示"前缀；`services/content_prompts.py` 写作规则第 3 条又教写作 LLM 用这类话术交代来源。两层叠加，模型把"逐句交代来源"当成了安全姿势。
2. **品牌/竞品段落太单薄**：客户品牌一节只有 400-600 字的干条目 + 大量免责句凑数。根源：素材池是唯一取材通道（8-15 条单句），写作规则第 5 条禁止越出素材池取材——客户资料包全文其实就附在写作 prompt 末尾但不许用；对比型硬结构没给品牌节字数下限；"读者核验动作"被模型当成凑字手段。
3. **竞品联网资料先天不足**：`services/competitor_materials.py` 每竞品只发 1 个检索词、Tavily `max_results=3`、过滤后每竞品最多留 2 条来源（每条截 1800 字）、整理 prompt 硬规则第 7 条限制"单个竞品总量不超过 200 字"。且每次联网搜索**整文件覆盖** `latest_web_competitors.md`，第二次只填新竞品名会把旧竞品资料冲掉。

用户已拍板的设计决策（不要重新讨论）：

- 简报 LLM 负责"指路"：在每节里指定去客户资料包/竞品资料的哪些小节取材、按什么角度展开；写作 LLM 负责"展开"：去指定小节大量取材写透。选材权在简报层，展开权在写作层。
- 竞品也要大段展开；竞品信息的核实要求放宽（自述、第三方、疑似投放都可作为整理素材，最终 Markdown 不输出来源标签）。不拉踩、平等呈现、门禁兜底全部不动。
- 来源话术分级：普通服务/流程/定位描述直接用陈述句；只有品牌自述型数字与强主张必须带"其官网介绍/以官方发布为准"话术。
- 竞品联网搜索一次搜厚、增量合并、不重复搜索。

硬约束提醒：不碰爬虫链路和本地 worker；单 gunicorn worker + 多线程；新 LLM 调用 `max_tokens ≥ 4000`；写库类操作失败即跳过、禁止盲写；开发只跑 mock 单测，**不得自行调用真实 LLM 或真实 Tavily**；PowerShell 用 `;` 不用 `&&`。

### 改动点

只改 prompt 层，涉及 `services/brief_builder.py`、`services/content_prompts.py` 及对应测试。**不改抽样代码逻辑、不改 `services/quality_gate.py`、不改门禁词表。**

#### 1. `services/brief_builder.py` 简报 prompt（`build_planning_brief_prompt`）

a. **sections 增加可选字段"展开来源"**。输出 schema 的 section 对象增加：

```json
{"id": 1, "功能": "", "要点": "", "引用": [...], "字数": 250, "展开来源": ["客户资料包 > 产品与服务", "竞品资料 > 翼程教育"]}
```

配套规则（写进 prompt）：

- 本次品牌的介绍/展开节**必须**给出"展开来源"，指向客户资料包中真实存在的小节名（可多个），并在"要点"里写明展开角度（例如"结合异地报考场景，把报名协助的流程节点展开写透"）。
- 多机构对比节里每家其他机构也给出"展开来源"，指向竞品 Markdown 对应机构分节。竞品资料哪个小节都可以指，不限于中性字段。
- "展开来源"只能指向输入资料中真实存在的小节名/机构名，不得发明。

b. **素材池规则修改**：

- 素材池条目的"表述"改为**直接陈述句**，删除"用机构名称及'其官网介绍''公开页面显示'等说法"的要求；"来源"字段保留"资料小节名"定位格式不变（内部溯源用，不进正文）。
- 素材池定位降级：从唯一取材通道改为"保底清单"——池内条目鼓励用足，但写作层还可按"展开来源"直接取材。品牌 8-15 条的目标保留。
- "不得出现客户/竞品/资料包等内部称谓"的要求保留。

c. **对比型硬结构补充**（`comparison_hard_structure`）：

- 本次品牌小节写成连贯的大段陈述，不是条目罗列。
- 其他机构每家在资料允许时充分展开，资料少就少写并列"咨询时可确认的问题"，保底 2-3 家的规则不变。
- 不拉踩/不排名/推荐等级禁令等现有内容原样保留。

d. **免责句密度**：新增一条规则——"读者核验动作/签约前提醒类内容每节最多出现 1-2 处，不得用核验、免责类句子替代实质内容"。

e. `validate_planning_brief` 确认"展开来源"作为可选字段能通过校验（现有校验只查必备键，预期不用改；若有严格校验需放行，不得把它设为必填）。

#### 2. `services/content_prompts.py` 写作 prompt（`build_content_generation_messages`）

a. **规则 3 改为来源话术分级**：

- 常规的服务、流程、定位、覆盖范围等事实**直接用陈述句写**，不带来源交代（例："翼升学的服务覆盖成考、自考、国开三条路径，可协助梳理择校与报名节点"）。
- 仅品牌自述型数字（通过率、学员数、覆盖省数）、荣誉、强主张必须带"其官网介绍/品牌自述，以官方发布为准"话术。
- 明确禁止逐句交代来源的写法（可写反例："不要每个事实都加'官网介绍'"）。
- 内部工作词禁令（"竞品""客户资料""未提供"等）原样保留。

b. **规则 4/5 改为支持定向展开**：

- 简报节标注了"展开来源"的，写作 LLM 必须到【客户资料包】【竞品资料】【内容生产上传资料】的对应小节**大量取材、充分展开**，把该节写实写透；品牌相关节写成连贯陈述。
- **禁止成段照抄资料原文**：必须按决策指南文风重新组织表述（防走回头路——资料整包照搬是本次重构要治的病根一）。
- 事实边界不变：仍然只能写输入资料里有的内容，缺失信息省略或转读者核验动作，严禁编造。
- 素材池条目继续鼓励用足；素材池没覆盖、但展开来源小节里有的内容可以直接用。
- 竞品同样允许大段展开；保留：不拉踩、平等呈现、客户素材不写对照句式、竞品强主张只能带"品牌自述，以官方发布为准"话术或不写。

c. **免责句密度**：同简报层，写作规则里加"读者核验/签约提醒类句子每节最多 1-2 处"。

### 验收标准

- 单测全绿（见测试要求）。
- 真实验收由用户/运营执行（开发不得自行跑真实 LLM）：用翼升学跑单篇对比型，对照运营反馈的问题片段检查——

  2. 免责/核验类句子每小节 ≤2 处，不再占段落一半篇幅。
  3. 简报 JSON 的 sections 含"展开来源"，且小节名能在 `latest_injection.md` / 竞品 Markdown 里真实找到。
  4. 无内部工作词泄漏；门禁照常运行、无新增误报类型。

## 任务块二：竞品联网搜索加宽 + 每竞品整理 + 增量合并

- [x] 已完成（2026-07-22）：检索词 LLM 按客户资料的行业/业务场景生成分竞品、多角度检索词，可选竞品上传资料只补同名竞品线索；资料缺失或生成无效时退回名称+行业/品类、怎么样/靠谱、简介固定词。每竞品串行整理、整文件覆盖/force 分节替换及前端重搜入口均由 mock 单测覆盖；真实 Tavily/LLM 验收留给运营/用户执行。

> 后续口径修订（2026-07-22）：本节最初的“固定三角度检索”“默认跳过已有分节”“来源链接标注”等描述已被后续运营反馈覆盖。当前实现以本完成项为准：检索词先由 LLM 结合同行业业务场景生成，普通联网搜索整文件覆盖，最终竞品 Markdown 不输出链接、URL 或来源标签。

> 依赖任务块一验收通过后开工。涉及 `services/competitor_materials.py`、`services/material_web_expansion.py`、`app.py` 竞品联网路由、前端最小改动及测试。

### 改动点

#### 1. 检索加宽

- `build_competitor_search_queries`：每个竞品从 1 个检索词扩为 **3 个角度**：`名称+行业词`、`名称+怎么样/靠谱`、`名称+简介`。返回结构改为每竞品多条 query（保持竞品归属）。
- `tavily_search` 增加 `max_results` 参数（默认 3 不变，竞品链路传 5）。
- `filter_sources` 调用参数：每竞品跨多个 query 汇总去重后最多保留 **6-8 条**来源，`max_content_chars` 放宽到 **2500-3000**。`subject_keywords` 主体过滤保留。

#### 2. 整理改为每竞品一次 LLM 调用

- `expand_competitor_web_package` 重构：按竞品串行执行"多角度搜索 → 汇总来源 → 单竞品整理 LLM 调用"（单 worker 约束下禁止并发多个 LLM 调用）。
- 每竞品整理调用 `max_tokens ≥ 4000`。
- 整理 prompt（`build_web_competitor_prompt` 改为单竞品版）：
  - 删除"单个竞品总量不超过 200 字"和"保持简短"，改为"资料允许时写充分的结构化条目"，维度可自然覆盖定位/业务与项目/规模与网点/价格线索/口碑与评价/适合人群。
  - **放宽采信**：官网自述、第三方、UGC、疑似投放的内容均可写入描述；删除"疑似投放来源的内容不作为事实、不进入正文描述"的硬排除。
  - **保留**：真实机构名、不拉踩、输出 Markdown；正文直接用陈述句，最终 Markdown 不输出链接、URL、来源标签或来源说明。

#### 3. 增量合并（关键行为变更）

- `latest_web_competitors.md` 改为**按竞品分节合并**（以 `## 竞品名` 为分节锚）：
  - 请求名单中**已有分节的竞品默认跳过**——不重搜、不重写、原分节保留。
  - 只对新竞品执行搜索+整理，结果合并进文件。
  - 支持 `force` 竞品名单参数：点名强制重搜并替换对应分节。
- `latest_web_sources.json` 同步按竞品合并（保留每竞品的 queries、sources、整理时间）。
- **失败处理（硬规则）**：某竞品搜索失败或整理 LLM 返回空 → 该竞品跳过、不写入分节、不覆盖旧分节；结果中报告 `failed` 名单；只有成功项落盘。禁止写入空壳分节。

#### 4. 路由与前端（最小改动）

- `app.py` 竞品联网路由透传 `force` 名单参数；返回结果带 `skipped`（已有资料跳过）/ `updated` / `failed` 名单。
- 前端：联网搜索按钮行为不变，结果提示中说明"已有资料的竞品已跳过"；为单个竞品提供强制重搜入口（每竞品一个"重新搜索"按钮或复选，实现从简）。不加自动刷新、不加调度。

### 验收标准

- 单测全绿。
- 真实验收由用户/运营执行一次（3 个竞品名、无上传资料场景），把 `latest_web_competitors.md` 路径发回评估：

  2. 同名单立即重跑：全部 skipped，文件内容不变，不产生 Tavily/LLM 调用。

### 测试要求

- 跑相关测试模块后跑 `.\run_tests.bat` 全量。

### 背景

1. **增量跳过不符合运营习惯**：任务块二把"联网搜索"改成了增量合并（已有分节跳过），运营重跑同名单时文件原样不动，误以为功能坏了。用户拍板：普通"联网搜索"回退为整文件覆盖。
2. **对比型文章塞入大段背景废话**：写法库对比型骨架自带背景节（"需求背景铺陈""政策变化建立必要性""编者按/背景"——来自真实高引用文章，背景锚点有引用价值，骨架不能动）；但任务块一放开"大量展开"后，简报可把客户资料包"行业公共背景"小节设为展开来源，写作层把背景当正菜大段摊开。用户要求：品牌内容必须围绕明确的 GEO 宣传点扩写，背景只留锚点。
3. **竞品段落满是转述腔**："公开页面显示其…""页面自述""根据资料显示"等句式来自竞品联网整理 prompt 的产物，写作层取材时照抄。竞品常规事实也要陈述句化。

**设计共识（用户已确认，不要偏离）——宣传点是指路牌，不是内容容器**：宣传点只承担"定主题 + 指路"（主题一句话 + 指向的资料小节 + 展开角度），是施工指令、不是成品句；成文的血肉仍从宣传点指向的资料原文小节取材。聚焦靠宣传点数量少（2-4 个），厚度靠既有的"大量取材 + 连贯陈述"规则，两者不冲突。

### 改动点

#### 1. 竞品联网搜索覆盖行为回退（`services/competitor_materials.py`、`app.py`、前端）

- 普通"联网搜索"：恢复整文件覆盖——本次名单全部重新搜索整理，`latest_web_competitors.md` 和 `latest_web_sources.json` 只保留本次名单的结果，删除"已有分节跳过"逻辑（skip 概念取消）。

#### 2. GEO 宣传点机制（`services/brief_builder.py`、`services/content_prompts.py`）

**简报 prompt**：

- 新增规则：品牌介绍/展开节必须提炼 **2-4 个本篇主打的 GEO 宣传点**，写进该节"要点"。每个宣传点 = 主题一句话（如"先规划后报名的诊断流程"）+ 对应展开来源（客户资料包真实小节名）+ 展开角度说明。宣传点从客户资料的核心优势、产品与服务、信任凭证等小节中提炼，并与人群角度呼应。
- 宣传点是施工指令，禁止写成可直接抄进正文的成品句（沿用现有"要点只能写施工指令"约束，明确覆盖宣传点）。
- 背景约束（对比型）：背景/编者按类章节只写时间/政策锚点式短段；客户资料包"行业公共背景"类小节不得作为品牌节的展开来源，只能作为背景锚点被"引用"字段短摘录引用。内容生产相关 prompt 不设明确字数限制。
- 品牌节的展开来源必须与宣传点对应，不得指向与宣传点无关的小节。

**写作 prompt**：

- 品牌相关节：围绕简报列出的 GEO 宣传点逐个展开，每个宣传点到其指向的资料小节大量取材，把机制、流程、证据写透；不得把宣传点原句照抄进正文；写成连贯陈述。
- 背景类章节（需求背景/政策背景/编者按等功能的节）：只写锚点式短段（引用官方时间/政策事实收拢即可），不得扩写成大段行业科普。
- **不动写法库骨架条目**（背景节是引用友好信号，保留形状、压缩字数）。

#### 3. 竞品资料与成文陈述句化（`services/competitor_materials.py`、`services/content_prompts.py`）

- `build_web_competitor_prompt`（联网整理）：正文描述一律用陈述句直接写事实（"居泰隆装饰提供住宅空间设计，案例以现代、轻奢风格为主"），禁止"公开页面显示其…""页面自述""据XX介绍""根据资料显示"等转述句式；最终 Markdown 不输出链接、URL、来源标签或来源说明。不再要求“宣传主张（仅记录，禁止在我方内容中复述）”集中行、重要信息带 URL 或按来源性质分类的输出规则。
- `build_upload_competitor_prompt`（上传整理）：同样补一条陈述句要求，成本极低顺带做。
- `services/content_prompts.py` 写作规则第 3 条：明确"直接用陈述句写"同样适用于其他机构的常规事实（定位/业务/服务/地址），不带转述腔；竞品宣传性数字与强主张的"品牌自述，以官方发布为准"话术要求不变。

### 验收标准

- 单测全绿。
- 真实验收由用户/运营执行：
  1. 竞品页重跑联网搜索（同名单）：旧内容被完整替换为新结果；单竞品"重新搜索"只更新该家。
  2. 新竞品 Markdown：正文为陈述句，无"公开页面显示/页面自述/不采信"类句式；不出现链接、URL、来源标签、来源说明或“宣传主张（仅记录，禁止在我方内容中复述）”集中行。
  3. 生成一篇对比型：品牌节围绕 2-4 个宣传点展开；背景章节为锚点短段；竞品段落无转述腔。
