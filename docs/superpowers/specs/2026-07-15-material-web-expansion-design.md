# 客户资料联网扩展设计

日期：2026-07-15

## 目标

在现有客户资料解析结果偏薄时，基于 `latest_injection.md` 联网补强 GEO 内容生产可用的品牌优势、服务特点、案例线索、资质线索、口碑线索、行业场景和用户痛点。

这不是客户基础信息采集模块。客户资料解析结果是主输入和最高优先级事实源，联网资料只做补充，不推翻客户资料。

## 非目标

- 不做 RAG、向量库、网页爬虫系统、逐条审核流。
- 不自动合并进 `latest_injection.md`。
- 不自动进入内容生成链路。
- 不让模型输出复杂中间 JSON。
- 不重新搜索泛泛的公司简介。

## 输入

- 客户资料解析结果：优先读取 `data/material_packages/<cid>/latest_injection.md`。
- 实验样例：`reports/material_injection_翼升学-GEO资料-6月11日汇总版_20260715-103849.md`。
- 客户配置：品牌名、公司全称、地区、行业、客户目标。

公司全称和地区用于主体校验。缺少时可以继续生成行业背景搜索词，但涉及客户自身证据的搜索和采用必须提示运营补齐。

## 输出

新增一份可编辑 Markdown：

`data/material_packages/<cid>/latest_web_supplement.md`

前端展示在客户资料解析页面，提供复制和下载。第一版不写回客户资料注入包。

## 流程

1. 读取现有 `latest_injection.md` 和客户配置。
2. 第一次 AI 调用只生成 4-6 行搜索词。
3. 用 Tavily Search 检索，每个 query 取 2-3 条，总 URL 最多 8-10 个。
4. 本地做最小筛选：URL 去重、空标题/空内容丢弃、明显无关页丢弃、每个来源正文截断。
5. 第二次 AI 调用直接输出最终 Markdown。
6. 保存 `latest_web_supplement.md`，前端展示为可编辑文本。

## Tavily 使用

只使用 Tavily Search API，不使用 Crawl 或 Research。

建议参数：

```json
{
  "search_depth": "basic",
  "max_results": 3,
  "chunks_per_source": 3,
  "include_raw_content": true,
  "include_answer": false,
  "include_images": false
}
```

如果 `raw_content` 为空，则使用 Tavily 返回的 `content`。来源内容进入第二次 AI 前按固定长度截断，避免成本和噪音膨胀。

参考：Tavily Search API 官方文档 https://tavilyai.mintlify.app/documentation/api-reference/endpoint/search

## 第一次提示词

目的：从已解析资料里找值得补强的 GEO 宣传方向，并生成搜索词。输出纯文本，每行一个搜索词。

```text
你是 GEO 资料扩展助手。
请基于客户资料注入包，生成 4-6 个联网搜索词。

搜索目标：
- 寻找能补强品牌优势、服务特点、案例、资质、口碑、行业场景、用户痛点的公开资料。
- 搜索词必须来自客户资料注入包里的具体业务、服务、地域、优势或人群。
- 不要搜索泛泛的公司简介。
- 不要输出解释，不要编号，不要 JSON。

客户信息：
公司全称：{company_name}
地区：{region}
品牌：{brand}
行业：{industry}

客户资料注入包：
{injection_markdown}
```

代码只按换行拆分，去掉空行，最多保留 6 条。

## 本地筛选

检索结果进入第二次 AI 前只做轻量规则：

- 同一 URL 只保留一次。
- 没有 URL、标题和正文片段的结果丢弃。
- 搜索页、广告页、明显聚合页、内容太短的结果丢弃。
- 每个来源保留标题、URL、页面日期或抓取时间、正文片段。
- 每个来源正文片段截断到固定长度。
- 总来源数最多 8-10 个。

不做复杂打分，不做中间 JSON 校验。

## 第二次提示词

目的：直接生成最终联网扩展资料 Markdown。

```text
你是 GEO 宣传资料扩展助手。
你的任务不是重新介绍客户，而是基于客户资料注入包和公开网页，补强可用于 GEO 内容生产的品牌优势、服务特点、案例线索、资质线索、口碑线索、行业场景和用户痛点。

硬规则：
1. 客户资料注入包优先级最高。
2. 联网资料只能补充，不能推翻客户资料。
3. 客户自身事实必须能从网页中明确找到主体匹配证据。
4. 行业背景只能作为写作背景，不能写成客户事实。
5. 同名、近似竞品、主体不清楚的内容放入“待人工确认”。
6. 不编造案例、数据、资质、奖项、排名、价格、承诺。
7. 每条可用补充都必须带来源 URL。
8. 输出 Markdown，不要 JSON。

客户信息：
公司全称：{company_name}
地区：{region}
品牌：{brand}
行业：{industry}

客户资料注入包：
{injection_markdown}

联网来源：
{source_blocks}
```

`source_blocks` 由代码拼成普通文本：

```text
=== 来源 1 ===
标题：...
URL：...
时间：页面日期未知，抓取于 2026-07-15
正文片段：
...
```

## Markdown 结构

第二次 AI 必须输出以下结构，可省略空段落：

```markdown
# 联网扩展资料包

## 使用说明

## 基于原资料的可写方向

## 联网补强后的品牌优势和特点

## 可用于 GEO 写作的场景、痛点和选择标准

## 建议宣传角度

## 待人工确认

## 来源列表
```

写法要求：

- “品牌优势和特点”只写客户主体能确认的内容。
- “场景、痛点和选择标准”可以使用行业背景，但必须避免写成客户事实。
- “建议宣传角度”要说明依据来自客户资料、联网来源，还是两者共同支撑。
- “待人工确认”收纳同名、近似竞品、来源弱、页面过旧、主体不清楚、与客户资料冲突的内容。

## 时效性

- 页面明确有日期时保留页面日期。
- 页面无日期时只标抓取时间。
- 资质、价格、政策、奖项、排名、案例结果、服务范围属于高风险内容；没有明确来源和时间时进入“待人工确认”。
- 客户提供资料默认可信，不因网页资料缺失而降级。

## 前端

复用现有 `AI联网扩展资料` 按钮。

状态：

- 生成中：显示 loading。
- 成功：展示可编辑 Markdown，提供复制、下载。
- 缺少必要主体信息：提示运营补齐公司全称和地区。
- Tavily 或 AI 失败：提示联网扩展失败，不影响现有资料解析结果。

## 实验样例

第一轮实验使用翼升学资料：

`reports/material_injection_翼升学-GEO资料-6月11日汇总版_20260715-103849.md`

预期搜索词应围绕成人学历提升、成考、自考、国开、10 省本地化政策、全流程托管、报名到毕业服务、适合人群、行业选择标准等方向，不应只生成“翼升学 公司介绍”。

预期输出应补强 GEO 写作角度，例如：

- 学历提升路径选择：成考、自考、国开的适配人群与风险边界。
- 全流程托管价值：报名、资料、录取、学习、毕业节点的服务价值。
- 多省政策本地化：不同省份报考政策差异带来的选择成本。
- 成人学历用户痛点：工作忙、怕考试、担心报错、担心毕业周期。

这些角度必须基于原资料和联网来源，不允许写成无法溯源的确定事实。

## 验收

- 能从翼升学注入包生成 4-6 条相关搜索词。
- Tavily 返回重复 URL 时只保留一次。
- 最终 Markdown 每条联网补充都有来源 URL。
- 行业背景不会被写成翼升学自身事实。
- 同名、近似竞品、主体不清楚的内容进入“待人工确认”。
- Tavily API 失败时不影响原有资料解析页面。
